# Message Viewer (Go)

Локальный веб-просмотрщик истории JetStream с фильтром по времени, subject-фильтром, лимитом строк, динамическими колонками из JSON, окном полного сообщения и экспортом CSV. В UI добавлены выбор Kafka/RabbitMQ как будущих адаптеров-заготовок.

## Возможности

- NATS JetStream: чтение с выбранного времени, фильтр по stream и subject.
- Период `С` / `По`, быстрые диапазоны 15 минут, 1 час, 6 часов, 24 часа, 7 дней.
- Настройки NATS URL, username/password или token, stream, subject, максимальное число отображаемых сообщений, тайм-аут и предел просмотра.
- Таблица с общими полями NATS (`time`, `subject`, stream sequence, consumer sequence), всеми найденными полями JSON (включая вложенные `payload.temperature`) и заголовками (`header.*`).
- Клик по строке открывает pretty-printed payload и NATS headers; экспорт результата в CSV.
- Временная JetStream-подписка. Именованный durable consumer не создаётся.
- Kafka и RabbitMQ представлены только выбором в UI и возвращают явное сообщение, что адаптер не реализован.

## Требования

- Go 1.23+
- NATS Server с включённым JetStream и существующим stream, который хранит сообщения нужного subject.
- Доступная для машины, на которой запущен просмотрщик, NATS TCP-точка.

> Обычный Core NATS не хранит историю. Чтобы читать произвольный период, сообщения должны быть записаны в JetStream stream и ещё не удалены политикой хранения.

## Запуск

```bash
cd message-viewer
go mod tidy
go run .
```

Откройте `http://127.0.0.1:8080`. По умолчанию сервер принимает соединения только с этой машины.

Сборка бинарника:

```bash
go build -o message-viewer .
./message-viewer
```

Чтобы открыть UI из другой машины локальной сети:

```bash
LISTEN_ADDR=0.0.0.0:8080 ./message-viewer
```

В этом режиме не выставляйте порт в публичный интернет. Приложение не имеет встроенной пользовательской аутентификации; ограничьте доступ firewall или поставьте reverse proxy с аутентификацией. Учитывайте, что NATS-пароли и token вводятся в браузере и отправляются локальному backend. Пароль и token не сохраняются в localStorage.

## Подключение к NATS

1. Введите адрес NATS, например `nats://192.168.6.38:4222`, если этот адрес и порт реально доступны с хоста, где запущен viewer.
2. Введите имя stream — его можно проверить кнопкой «Проверить подключение».
3. Укажите subject. `>` — все subject, покрываемые выбранным stream; `events.>` — все подпоследовательности с префиксом `events.`.
4. Установите период и лимит показа.
5. Нажмите «Загрузить сообщения».

Адрес/порт выше — пример, а не подтверждение, что NATS в конкретном кластере опубликован наружу. Если NATS Service имеет только ClusterIP, запустите viewer в кластере либо настройте доступный NodePort/port-forward.

## Поведение лимитов

- «Сколько показать» — максимум строк в UI, от 1 до 5000. Приложение сохраняет последние сообщения из выбранного диапазона.
- «Макс. сообщений просмотреть» — сколько сообщений максимум разрешено прочитать, чтобы найти последние записи; от 1 до 500000. Если предел достигнут, API помечает ответ как усечённый.
- «Тайм-аут» — предельная длительность сканирования. При долгом диапазоне сузьте период или увеличьте этот лимит.
- Чтение выполняется временной JetStream push-подпиской; максимальная длительность и предел сканирования настраиваются в UI.
- Поля JSON объединяются динамически по всем строкам результата. Объекты разворачиваются в dotted paths, массивы остаются JSON-строкой.

## Диагностика

- `stream not found`: проверьте имя stream и подключение к правильному NATS account.
- `no messages found`: проверьте subject, часовой пояс, период и retention. Запрос отправляет timestamps в UTC.
- Ошибка подключения из браузера: проверьте NATS URL, credentials и сетевую доступность с машины, на которой работает Go-процесс.
- Недостаточно памяти у JetStream: проверьте storage и memory/file limits на NATS Server; просмотрщик не создаёт stream и не исправляет настройки хранения.
